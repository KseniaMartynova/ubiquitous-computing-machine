# Искусственные данные для задания 7

Это **фикстуры для тестов**, не результаты эксперимента. Числа времени, память, CPU, контрольные суммы и image ID придуманы; commit состоит из сорока нулей. В manifest есть отметка `synthetic=true`. Она справочная: анализатор обрабатывает эти файлы по тем же правилам, что реальные данные, без отдельной ветки для фикстур. Обращаться к Git, Docker и запускать матричные программы не нужно.

Скопируй содержимое этого каталога в `runks/fixtures/analyze/` репозитория эксперимента. CSV имеют настоящий заголовок из 23 полей и расписание принятого `run_grid.py` с `shuffle_seed=20260818`. Manifest содержат только сведения, нужные для задания 7, а не имитацию полного отчёта о пакетах машины.

## Сценарии

| Ключ в `expected.json` | CSV | Размеры | Повторы | Строк данных | Строк сводки / регрессий |
|---|---|---|---|---|---|
| `power` | `power.csv` | 16, 64, 256, 1024 | 5 | 240 | 48 / 12 |
| `noisy` | `noisy.csv` | 16, 64, 256, 1024 | 5 | 240 | 48 / 12 |
| `single` | `single.csv` | 16 | 1 | 12 | 12 / 12 |
| `unequal` | `unequal-small.csv`, `unequal-large.csv` | 16, 64 / 256, 1024 | 5 / 3 | 120 + 72 | 48 / 12 |

У каждого CSV есть соседний `<имя>.manifest.json`. Разные сценарии не объединяются: они содержат повторяющиеся размеры и проверяются отдельно. Для каждого `--all` получается восемь PNG; при `--operation multiplication` — два PNG и строки только этой операции (три реализации).

## Как построены времена

Во всех сценариях основа — `T(n)=a*n**2.5`. Коэффициент:

```text
a = 1e-8 * implementation_factor * operation_factor
implementation_factor: mkl=1, openblas=1.25, numpy=1.5
operation_factor: cholesky=1, lu=1.5, multiplication=0.5, svd=4
```

В `power` пять повторов равны основе, умноженной на `[0.8, 0.9, 1.0, 1.1, 1.2]`. Поэтому Q1 = `0.9*T`, median = `T`, Q3 = `1.1*T`, а все регрессии имеют `c=2.5` с нулевым в точной арифметике интервалом.

В `noisy` основа для четырёх размеров дополнительно умножена на `exp(delta)`, где `delta=[0,0.16,-0.12,0.20]`. Множители повторов те же. Получается ненулевая ширина интервала; для всех реализаций и операций:

```text
c            = 2.5230831206542232
c_ci95_low   = 2.281711209130916
c_ci95_high  = 2.7644550321775303
```

У `mkl/cholesky` в этом сценарии `a=9.493288668428895e-09`; у остальных коэффициент меняется пропорционально указанным множителям. Ответы рассчитаны из нормальных уравнений линейной регрессии и критического значения Стьюдента `4.302652729696142` для двух степеней свободы, независимо от вызова `scipy.stats.linregress`.

`single` содержит основу без множителей: Q1 = median = Q3, count = 1. Во всех двенадцати регрессиях `status=insufficient_sizes`, числовые поля пустые.

В `unequal` малые размеры имеют пять повторов, большие — три с множителями `[0.9,1.0,1.1]`. Медианы сохраняют точную степень `2.5`; при трёх повторах Q1 = `0.95*T`, Q3 = `1.05*T`. Число повторов берётся из manifest каждого блока, отдельный аргумент командной строки для него не нужен.

Память каждого повтора: `base+n+rep` кБ, где `base` равно 32768 для MKL, 24576 для OpenBLAS и 65536 для NumPy. В сводку попадает максимум по группе. Остальные диагностические поля исходных CSV в этом задании отдельно не сводятся.

## Формат ожидаемых ответов

В `expected.json` поле `cases` содержит четыре сценария. В каждом есть список `csv_files`, список размеров `sizes`, массивы `summary` и `fits`. Ключи записей соответствуют заголовкам выходных CSV из задания.

- JSON `null` в числовом поле регрессии означает пустое CSV-поле; это не строка `null` и не `NaN`.
- Сравнивай числа с `rel_tol=1e-9, abs_tol=1e-14`. Для обеих границ интервала точной степени в `power` и `unequal` допускается `abs_tol=1e-6`: очень узкий ненулевой интервал может возникнуть из-за округления логарифмов и корреляции. Для `noisy` действуют обычные строгие допуски — этот сценарий проверяет сам расчёт ненулевой ширины.
- Сопоставляй строки по операции, реализации, режиму и размеру (для регрессий — без размера). Порядок строк не является условием приёмки. При выборе одной операции бери соответствующее подмножество ожидаемых ответов.

## Команды проверки

Из корня репозитория эксперимента, в активированном окружении анализа:

```bash
python3 runks/analyze.py --csv runks/fixtures/analyze/power.csv \
  --sizes 16,64,256,1024 \
  --all --output-dir analysis/check7-power

python3 runks/analyze.py --csv runks/fixtures/analyze/noisy.csv \
  --sizes 16,64,256,1024 \
  --all --output-dir analysis/check7-noisy

python3 runks/analyze.py --csv runks/fixtures/analyze/single.csv \
  --sizes 16 \
  --all --output-dir analysis/check7-single

python3 runks/analyze.py \
  --csv runks/fixtures/analyze/unequal-small.csv runks/fixtures/analyze/unequal-large.csv \
  --sizes 16,64,256,1024 \
  --all --output-dir analysis/check7-unequal
```

Все четыре команды должны завершиться с кодом 0. Повторная генерация выходных таблиц и графиков разрешена. Для теста двух размеров или некорректных входов делай временные копии фикстур в unit-тестах; исходные прилагаемые файлы оставь неизменными.
